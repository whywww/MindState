## 开合与四态

`FlowerAssembler` 在 Editor 中为每层建立确定性的曲面变体，基础曲面仍采样 33 个姿态。离线烘焙把基础曲面和全部补偿合成为每片花瓣的最终顶点、法线、切线及包围盒；采样包含全局补偿节点和各层时间节点，并在区间的 1/4、1/2、3/4 处检查误差、按需细分。位置误差上限为 0.0001 Unity 单位，法线及切线方向误差上限为 1°。

正式播放直接从 `StreamingAssets/FlowerPlayback.bin` 加载只读 GPU 缓冲。`Pearl.shader` 的顶点修改函数在颜色和阴影通道使用同一个采样函数，连续插值相邻姿态；主花和回声花均不在每帧插值 CPU 顶点、重算法线或上传花瓣网格。回声花保留原来的低密度网格，并在同层花瓣间共享基础姿态缓冲。CPU 保留状态平滑、花瓣变换、根部对齐和艺术摆动。每个缓存姿态的包围盒取实际顶点的 min/max，并增加 0.00002 Unity 单位的总尺寸安全边距；渲染裁剪使用相邻姿态包围盒的并集。光流的半径驱动单独对姿态包围盒中心和尺寸插值，再按当前花瓣变换计算，路线与遮罩使用同一个连续半径，不能用裁剪包围盒驱动动画。回声 GPU 根部和姿态使用同一个逐帧进度，不应用小幅变化门槛。几何查询 `PetalMesh`、`LayerMesh`、`SharedMesh` 仅在显式调用时重建诊断网格，会产生读回或 CPU 计算开销，不应放入正式播放的每帧循环。

四态决定开合目标：澄明 90%、凝聚 10%～13%（5 秒呼吸周期）、漫游 100%、幽微 35%。四态共用一个整花姿态：澄明直立、凝聚收成花苞、漫游整体侧倾 5°、幽微低头 4° 并轻微下沉。原动态摆动叠加在标准姿态上：澄明 8 秒呼吸、漫游 7～11 秒行波、幽微外层下垂。每态另有一组 `artLooks` 外观参数（强调色、色相拉近、亮度、饱和度、gloss、边缘光、自发光、曝光、灯光增益/漂移），四色分别为冷青白、琥珀、蓝紫、烟紫。强调色不做四色相加：只有前二权重差达到 0.45 时才把颜色族提交给领先态，否则保持上次提交的颜色，避免接近 50/50 时混成灰粉；手动四态切换仍按预览渐变取色。外部输入的颜色再经过 4 秒一阶平滑，脑电剧烈跳动时只连续漂移、不会硬切；6 秒预览本身已是渐变，不再叠加这层平滑。整花姿态与开合仍按四维权重凸组合。手动切换 6 秒；流式输入用 6 秒临界阻尼平滑（约 5 秒合上一半，张开同节奏，起手速度为零，不会突然合拢）；灯光使用独立平滑。面板四态按钮是虚拟脑电预设：专注/放松滑条在 6 秒内平滑移动到该态目标值（80/80、80/20、20/80、20/20），花朵每帧跟随滑条值并经显示层映射。

`FlowerEcho` 是常驻的回声花：50% 大小，中心与主花在水平面内相距 1.70 倍全开花冠半径；间距跟随回声花自己的平均开合——记忆花较大时保持 1.70 倍并留在主花侧后方，记忆收成花苞后才收到 1.30 倍；相机不随状态移动，回声自己收成花苞时只小幅放大（8%）并朝观众挪 0.12；主花合拢时回声再沿视线往后退 0.05、朝主花方向移 0.04 倍相机距离，始终留在主花侧后方的次要深度；每 0.5 秒记录一次状态，对相邻记录做线性重建，再对 10～45 秒前（最近 10 秒不参与）的滑动窗口按时间积分求权重、开合与灯光平均值；窗口两端的部分区间逐帧参与，显示不再每半秒跳一档，用低密度双面网格呈现这段时间的整体印象（各状态所占时长的混合），不再逐秒追主花；朝向按平均状态的转速自行缓慢旋转。材质压到冷灰蓝记忆色（亮度 0.55、饱和 0.40、自发光关闭），强调色再单独平滑 1.5 秒，只作背景回声，不抢主体。`FlowerRibbons` 在花外画一条丝线，像笔尖描线：一条 192 段的开放光带，亮头始终单向绕花前行（一圈 12～20 秒，专注越快、放松越慢，从不折返），身后拖尾按 2.2 次幂渐隐，可见长度约 0.5～0.7 圈（放松越长，硬上限 1.5 圈）。艺术模式下永远只有这一条，不随四态增减；进入/离开艺术模式各 1.2 秒淡入淡出。路线形状直接由 0～1 的专注/放松（2.5 秒平滑）驱动：专注越高线越紧、越高、越细、绕行越快；放松越高线越松、越低、拖尾越长；专注高且放松低时起伏和抖动最大。半径按当前花冠水平半径换算，顶点下限 1.18 倍，着色器从 1.02 倍起遮罩，因此不压花瓣；颜色取平滑后的强调色。取景按主花全开花瓣与回声花的实际顶点计算，焦点向主花偏 65%，让主花落在画面中间偏右、回声花贴左侧；取景距离再收到该值的 0.83，因为含景深的包络远大于可见轮廓，收紧后两朵花在四态里都不出画。丝线环不参与取景，线环尾部允许延伸到画面外。相机在四态间完全固定：谁收成花苞，谁就朝观众方向挪 0.25、整体放大 14%（以全开中心为锚点原地放大），主花与回声、丝线整簇再沿画面竖直下移 0.05 倍、水平朝画面中心移 0.06 倍相机距离，替代原来的相机推近与目标点上抬，让花苞留在画面中部、主花始终靠近中心。左侧面板默认隐藏、按 H 显示，不参与取景。取消艺术模式时整体隐藏。

Unity 主线程、`flower.Ready` 后调用：

```csharp
flower.SetBloomProgress(0.5f); // 退出四态，显示标准开合
flower.PlayBloom();           // 从闭合重播
flower.SetArtState(FlowerArtState.Clarity);
flower.WaitForArtBrain();
flower.SetBrainMetrics(attention01, relaxation01, signalValid: true);
flower.SetFrozen(true);
flower.ResetArt();
```

注意力 A、放松度 R 的原始权重为 AR、A(1−R)、(1−A)R、(1−A)(1−R)。显示层再叠加 180 秒中位数基线、绝对/相对增益，并在四个象限上做带主态加成的 softmax（β=16）与 2% 迟滞，使 55/45 这样的输入也落在明确主态而不是平均态；除非挑战态领先 2%，否则保持已提交主态。原始权重保留在 `RawBrainWeights` 供界面与诊断使用。无效值不刷新有效时间；外部输入五秒无有效数据后保持上一状态，状态栏显示「正在重新感知」，有效数据恢复后继续跟随。

## 缓存维护

造型以 `ExhibitionPeony.asset` 和 `HeroPetal.prefab` 为准，外观以 `TargetAppearance.asset` 为准。改变几何参数或几何源码后执行 `Tools/Bake.ps1`，然后验证、构建。单纯修改外观使用 `RefreshAppearance()`。

完整生成顺序：底部补偿、尖角、层间搭接、外层平滑及修正、中层修正及平滑、内层修正及平滑。每次从基础曲面开始，不读取历史报告或缓存快照，不把已有结果重复叠加。

补偿缓存和播放缓存各保留一个当前格式，源码签名由生成与构建共用。播放缓存的签名覆盖播放代码、烘焙代码和着色器；构建拒绝缺失或过期缓存。补偿校验只比较几何相关来源，所以修改播放代码或着色器不会误使底层补偿失效。禁止只更新签名而跳过生成。加载失败会释放已分配资源并停止组件，不在运行时退回重算几何。

`Tools/Bake.ps1` 默认完整重建补偿及播放缓存。修改播放代码或包围盒元数据后，使用 `Tools/Bake.ps1 -PlaybackOnly` 只重新生成播放缓存，前提是底层补偿来源校验通过；该模式保留原补偿签名。`-flowerCpuReference` 仅在 Editor / 验证构建启用原 CPU 路径。正式构建不接受该开关。

## 验证与产物

`Tools/Verify.ps1` 先验证原 CPU 参考路径，再通过与顶点着色器共享的采样函数执行 GPU 回读比较，检查主花与回声花、根部、包围盒、切线方向、跳转/反向进度、零顶点上传以及释放后重建。新增 GPU 运动连续性回归验证 30/60/120 Hz 下的闭合、呼吸、历史窗口边界、所有缓存节点、冻结恢复和更新率一致性；历史线性信号使用解析积分作独立对照，并检查花瓣零上传、更新零分配。原有回归验证标准路径、四态切换、冻结与根部连接，并检查回声花历史概括与间隙、单条丝线的离花间隙与逐帧路线连续性、亮头单向前行、专注/放松对路线形状的驱动、颜色提交与逐帧连续性、显示层映射和截图产物。接触扫描是离散采样，不能据此宣称连续时间、所有角度零穿插；已接受的动态接触见当前问题文档。

验证结果、烘焙统计及日志统一写入 `Outputs`，重复执行覆盖本轮输出。正式程序仅保留 `Builds/Windows`，BrainLink 的本机环境保留在 `Builds/BrainLinkTools`。验证构建可以重新生成。

## 性能对比

先运行 `Tools/Build.ps1 -Validation`，随后依次运行 `Tools/Performance.ps1 -Reference` 和 `Tools/Performance.ps1`，不要同时运行两组测试或另一份 Unity 场景。两组均使用相同的 Development 验证程序，在 1920×1080、原有 4×MSAA 和相同画质下关闭垂直同步、统一使用场景原有的 240 FPS 上限，预热 10 秒后采集 120 秒，覆盖往返开合、四态切换、脑电跳变和冻结恢复。隐藏/最小化窗口会跳过正常呈现，因此采集程序显式渲染 1080p HDR 目标，并通过单像素读回等待 GPU 完成。这种测量包含同步成本、取消通常的 CPU/GPU 重叠，属于保守帧耗时，不等同于窗口呈现 FPS。之后另行截图四态，不把截图耗时计入性能结果。

结果写入 `Outputs/PerformanceBefore` 和 `Outputs/PerformanceAfter`，包含逐帧 CSV、六个测试阶段各自的帧耗时分位数、CPU/GPU/墙钟时间分位数、花朵更新分配和顶点上传次数、几何内存及初始化耗时。GPU 计时不可用时明确标为 unavailable。验收目标为帧耗时 P95 ≤16.67 ms、P99 ≤20 ms；正式花瓣播放应无顶点上传、无持续 GC 分配。不能用编辑器或禁用渲染的批处理速度代替独立程序的帧率。

## 闭合连续性录像

先构建验证程序，再运行 `Builds/Validation/MindState.exe -verifyMotion -captureClosing -logFile Outputs/ClosingCapture.log`。该检查先执行运动回归，然后用预热的非恒定历史录制 600 张 1280×720、4×MSAA 图像，固定步长为 1/60 秒，覆盖从澄明到凝聚及其呼吸。图像位于 `Outputs/ClosingFrames`，半径/回声开合/亮头进度位于 `Outputs/MotionValidation/Closing.csv`。用 FFmpeg 以 60 FPS 编码为 `Outputs/ClosingContinuity.mp4`，不使用补帧或运动模糊。录像是固定步长视觉检查，性能仍需单独运行 120 秒采集。
